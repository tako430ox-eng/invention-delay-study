# 改善策と作業の決まり(2026-11-16 固定)
作成: Claude 側。review/review_2026-11-16.md の反省点ごとに、具体的な改善策を1つずつ対応させる。

| 反省点 | 改善策(具体的な手順) | 今回の実行 |
|---|---|---|
| 1. 先行研究を最初に調べなかった | 新しい問いや作業を始める前に、先行研究を検索して「既に言われていること」を3行で書く。書けない場合は作業を始めない | C型の調査の前に実施(03 の1節) |
| 2. 手段が目的になった | 作業ごとに「この結果で、問いへの答えがどう変わるか」を1行で先に書く。書けない作業はしない | 各文書の冒頭に記載 |
| 3. 情報が増えない作業を続けた | 同じ形の作業を2回して新しい情報が出なければ、3回目はしない | 作り物の課題、AI同士の往復はやめたまま |
| 4. 人の手を運び役に使った | 依頼者の手が要るのは、データの取得など代わりが無い場合だけ。1回にまとめて頼む | Potter の元データの取得だけを依頼 |
| 5. データの列の意味を確かめなかった | 事例を選ぶ前に、データの全ての列の定義を元の文書で確かめて書き出す。複数の物差しがあれば、両方で結果を出す | 30件を両方の列で再計算済み(review 2.1)。元データ取得後に全件で実施 |
| 6. 判定者が1人だった | 判定の一部を、事情を知らない別の判定者(新しい文脈)が、同じ基準と同じ資料だけで判定し、一致度を出す | 30件の再判定(02) |
| 7. 予想が外れても何も変わらない形だった | 予想は「外れたら、どの考えを捨てるか」を併記して書く | 03 の予想 |
| 8. 定義があいまい(N、R と U の境界) | 判定の条件を「満たす/満たさない」で答えられる項目に分解する | 03 の4条件 |
| 9. 再現できない(元データ未保存) | 使ったデータは必ず共有フォルダに保存し、ハッシュを記録する | 元データの取得後に保存 |

## やめること
作り物の課題、AI同士の文書の往復、問いに答えない手順の整備。

## 続けること
事前に基準と予想を固定する、出典の文言を付ける、否定的な結果をそのまま書く。
